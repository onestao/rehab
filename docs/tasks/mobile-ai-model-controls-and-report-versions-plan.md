# 移动端 AI 模型控件与报告多版本实施计划

> 生成日期：2026-07-11  
> 状态：已实施并通过自动化验证  
> 实施方式：确认后分两个内部阶段完成，最终作为一套功能交付  
> 范围：功能级模型选择、推理深度、收藏与最近使用、备用模型授权、报告重新生成与多版本

---

## 背景

当前各功能页通过 `ai-task-settings.js` 挂载原生模型下拉框和五段推理深度按钮。它能完成配置，但存在明显的移动端体验问题：

- “连接 · 模型”原生下拉框占用整行，视觉上接近管理后台表单。
- “自动 / 关闭 / 低 / 中 / 高”五段按钮长期占据较大面积，重要性超过主任务。
- 模型配置与生成动作的关系不够直观，用户不容易判断配置影响当前请求还是整个应用。
- 不同功能的交互上下文不同，但当前统一渲染成相同的大块表单。
- 体重报告与训练总结再次生成时会覆盖同周期旧结果，无法真正比较不同模型的回答。
- 已生成的体重报告没有重新生成入口。
- 周总结与降载判断写入同一周期记录，后生成的结果会覆盖前一个结果。
- 备用模型是否会被自动使用缺少明确授权与结果透明度。

本计划保持现有静态、本地优先 PWA 架构，不引入后端或 bundler。

---

## 已确认决策

1. 模型需要高频切换，不能隐藏成低频高级设置。
2. 切换模型只影响下一次生成，不立即发送请求。
3. 每个功能分别记忆并持久保存模型与推理深度。
4. 主界面使用紧凑模型按钮和独立推理深度图标，不保留大块表单。
5. 推理深度点击后打开紧凑选择菜单，不使用循环点击或滑动切换。
6. 快速菜单选中后立即保存并关闭；收藏操作不关闭菜单。
7. 各页面按实际工作流放置控件，不强制同一位置。
8. 食物文字识别和图片识别各自显示一条紧凑操作栏，两套配置同时可见。
9. 目标方案等单一生成表单在主按钮上方显示紧凑工具栏。
10. 训练计划长表单使用吸附底部工具栏。
11. 主按钮显示“连接图标 + 紧凑模型名”，完整连接信息放入选择菜单。
12. 模型短名只做展示裁剪，绝不改变模型身份或合并相似版本。
13. `GPT-5-5` 与 `GPT-5.5` 必须分别显示，不得归一化。
14. 无 `displayName` 时可移除明确的服务商前缀，但剩余大小写、连字符和句点原样保留，例如：
    - `claude-sonnet-4-5` -> `sonnet-4-5`
    - `claude-sonnet-4.5` -> `sonnet-4.5`
15. 收藏模型全局共享，收藏身份使用 `profileId + modelId`。
16. 最近使用按功能独立保存。
17. 模型菜单顺序为：收藏、当前功能最近使用、按连接分组的全部模型。
18. 搜索按需展开；模型较多时提供搜索入口。
19. 推理深度使用用户化名称与视觉状态，同时保留底层 `off / auto / low / medium / high`。
20. 设置页改为紧凑任务列表，并用完整配置抽屉管理主模型、备用模型和恢复默认。
21. 备用模型是否自动使用由用户在设置页逐功能授权，默认关闭。
22. 用户开启自动回退后可以自动使用备用模型，但每次回退都必须明显提示并记录实际响应模型。
23. 未开启自动回退时，主模型失败后停止请求，并提供“使用备用模型重试”。
24. 离线复盘保留，但默认不使用，只能由用户明确点击生成。
25. AI 失败时不能自动生成并保存离线复盘。
26. 报告与总结每个结果类型最多保留最近 3 个版本。
27. 同一时间只显示一个版本，复用 AI 教练的左右切换按钮与 `x/y` 计数交互。
28. 首版不提供答案收藏，避免与模型收藏混淆。
29. 周总结与降载判断独立保存，但共享 `summary.weekly` 的模型和推理深度配置。
30. 既有记录需无损迁移为第一个版本。
31. 能复用的现有 AI 教练代码必须复用；目标是移动端轻量，不并存两套模型选择器、收藏逻辑或版本切换器。

---

## 目标

1. 让用户在移动端一眼看到当前模型和推理深度，并能用一次点击进入选择。
2. 让配置位置与“影响下一次生成”的行为关系清楚。
3. 保持按任务路由的模型选择与能力过滤，不破坏现有 AI 调用接口。
4. 提供全局收藏和功能级最近使用，降低频繁比较模型的操作成本。
5. 让报告和总结支持重新生成、保留最近版本和查看实际响应模型。
6. 让备用模型的授权、执行和结果完全透明。
7. 保持所有交互可键盘操作、可被屏幕阅读器识别，并适配底部安全区和虚拟键盘。
8. 通过抽取共享代码和删除旧实现控制净增体积，不以复制现有能力换取开发速度。

---

## 非目标

- 不引入后端、账号系统或云端模型偏好服务。
- 不并行请求多个模型。
- 不在首版提供答案并排对比或自动差异分析。
- 不在首版提供答案收藏或无限版本历史。
- 不允许用户用短名替换原始模型 ID。
- 不重新设计 AI provider、凭据或模型缓存底层。
- 不让未配置的备用模型被系统自行选择。
- 不新增第二套模型选择弹窗、第二套收藏存储或第二套版本切换样式。
- 不为搜索、抽屉、图标或版本切换引入新的第三方依赖。

## 复用与体积硬约束

### 必须复用的现有能力

| 现有能力 | 复用方式 |
|---|---|
| `#aiModelPickerSheet` | 提升为全应用唯一模型选择抽屉，不为各功能重复创建 modal |
| AI 教练模型行、星标按钮和选中状态 | 抽成共享渲染/事件逻辑，AI 教练改为调用共享组件 |
| `adviceModelVisual()`、provider 图标与主题变量 | 提升为共享模型视觉 helper，不复制 provider 识别正则 |
| `adviceModelStarKey()` 与收藏交互 | 迁移为 `profileId + modelId` 的共享收藏实现，并删除旧的 provider 级重复逻辑 |
| `.advice-version-switcher` 及左右切换交互 | 泛化为共享版本切换器，AI 教练、报告和总结使用同一 DOM 结构与样式 |
| `sheet-drag.js` | 复用移动端下滑关闭，不另写手势引擎 |
| `nav-stack.js` | 复用系统返回键/应用返回栈行为 |
| `a11y-focus-trap.js` | 复用焦点约束与关闭后焦点恢复 |
| `haptics.js` | 复用已有轻触觉反馈 |
| `render-safe.js` / `escapeHtml` | 复用安全渲染，不新增不受审计的 HTML 拼接路径 |
| Material Symbols 本地字体子集 | 优先使用已打包图标，不增加图片、SVG 包或远程资源 |

### 删除与收缩

完成共享组件后必须删除或收缩以下旧实现，不能保留双轨代码：

- 删除 `ai-task-settings.js` 中被替代的原生 `createSelect()` 和五段 `createReasoningControl()` 渲染路径。
- 删除 AI 教练中已迁移到共享组件的模型行排序、星标状态和重复事件绑定代码；仅保留 advice taskId 与页面刷新适配器。
- 将 `.model-picker-*` 基础规则保留一份；页面文件只保留宿主布局，不复制控件外观。
- 报告和总结复用同一版本数组 helper，不分别实现追加、裁剪、切换和删除。
- 旧数据兼容采用小型归一化 helper，不长期维持两套写入格式。

### 加载与运行时策略

- 共享抽屉只保留一个空壳，模型行在用户点击时按需生成。
- 搜索使用现有模型数组的轻量内存过滤，不引入索引库或 worker。
- 不预渲染所有任务的模型列表；主页面只加载当前模型摘要。
- 收藏与最近使用只保存引用，不复制完整模型元数据。
- 最近使用每任务最多 3 个，报告版本每结果类型最多 3 个。
- 动画仅使用 CSS transform/opacity，并尊重 `prefers-reduced-motion`。

### 体积验收

- 实施前记录 `npx --yes size-limit` 基线，实施后附上逐预算差值。
- 不得在未再次获得用户确认的情况下提高 `.size-limit.cjs` 任何上限。
- `ai-bundle`、`records-bundle` 和 `generated-css` 必须继续通过现有门槛。
- 若新功能导致某一预算接近上限，优先删除重复代码、延迟渲染或下沉纯 helper，而不是调高限制。
- 新增文件必须被 `check:size-limit-coverage` 覆盖，不能通过改名逃逸体积检查。

## 共享 UI 设计

### 紧凑模型按钮

主界面形式：

```text
[连接图标] sonnet-4.5  v
```

规则：

- 移动端建议最大宽度约 `132px`，宽屏建议最大宽度约 `180px`。
- 单行显示并使用省略，不允许挤压推理图标或主操作按钮。
- 首选已有 `displayName`；缺失时使用保守的短名函数。
- 完整模型名、连接名和能力信息始终显示在选择菜单中。
- 同名模型来自多个连接时，按钮追加简短连接提示或依靠不同连接图标消除歧义。
- 选择和持久化始终使用 `profileId + modelId`，绝不使用短名作为身份键。

### 模型选择抽屉

顺序：

1. 收藏模型。
2. 当前任务最近使用，最多 3 个。
3. 按连接分组的全部兼容模型。

行为：

- 当前模型显示勾选。
- 点击模型立即保存、轻触觉反馈并关闭抽屉。
- 点击收藏星标只更新收藏，不切换模型、不关闭抽屉。
- 收藏全局共享，但只展示满足当前任务能力要求的模型。
- 可用模型超过建议阈值时显示搜索图标；点击后再展开搜索框。
- 模型条目主行显示完整模型名，副行显示连接名和能力标签。
- 不可用模型若必须保留展示，应明确标记原因且不可选择。

### 推理深度图标

底层值保持不变，界面使用以下语义：

| 内部值 | 显示名称 | 主视觉建议 |
|---|---|---|
| `off` | 直接回答 | 灰色认知图标加关闭标记 |
| `auto` | 自动 | 蓝色自动闪光 |
| `low` | 轻量思考 | 紫色轮廓认知图标 |
| `medium` | 标准思考 | 金色填充认知图标 |
| `high` | 深入思考 | 炫彩认知图标加双闪光 |

实现约束：

- 优先复用已打包的 Material Symbols：`psychology`、`auto_awesome`、`block`。
- 高低层级通过同一图标家族的填充、装饰和颜色组合表达，避免五个毫无关联的图标。
- 不能只依赖颜色；轮廓、填充和装饰也必须不同。
- 图标按钮提供完整 `aria-label`，例如“推理深度：标准思考”。
- 点击打开紧凑底部菜单；菜单显示图标、用户化名称和原始档位小字。
- 当前模型明确不支持推理深度时，只允许兼容项，并解释禁用原因。

### 移动端行为

- 所有主要触控目标至少 `44 x 44px`。
- 模型列表使用底部抽屉，支持遮罩关闭、系统返回关闭和下滑关闭。
- 抽屉内部独立滚动并避让 `safe-area-inset-bottom`。
- 虚拟键盘弹出后搜索框和结果仍处于可视区域。
- 不依赖 hover；桌面 tooltip 只是补充。
- 快速菜单即时保存；完整设置抽屉保持打开，允许连续编辑。

## 数据模型与迁移

### 模型选择偏好

建议在 `data.db` 中新增：

```js
db.aiModelPickerPrefs = {
  favorites: [
    { profileId: 'profile-id', modelId: 'model-id' }
  ],
  recentByTask: {
    'food.text': [
      { profileId: 'profile-id', modelId: 'model-id' }
    ]
  }
};
```

规则：

- 收藏全局最多保留合理上限，例如 100。
- 每个任务最近使用最多保留 3 个。
- 删除连接或模型后不立即破坏数据；菜单只隐藏不可解析项，设置页可提示失效配置。
- 从 AI 教练现有 `provider::model` 收藏尽力迁移：只有能唯一映射到一个连接时才自动迁移；存在多个同名连接时不猜测。
- AI 教练随后也读取新的全局收藏，避免两套收藏源继续分叉。

### 任务路由与备用授权

在现有任务路由中增加显式策略：

```js
{
  primary: { profileId, modelId },
  reasoningDepth: 'auto',
  fallbacks: [{ profileId, modelId }],
  fallbackMode: 'manual' // 'manual' | 'automatic'
}
```

规则：

- 迁移旧路由时默认 `fallbackMode: 'manual'`。
- 仅存在 `fallbacks` 不代表允许自动回退。
- `automatic` 时运行层可尝试备用模型，但必须返回并记录实际模型元数据。
- `manual` 时主模型失败后不继续调用；UI 提供显式备用模型重试。

### AI 调用结果元数据

现有大量调用依赖字符串返回值，不能直接破坏接口。建议增加非破坏式 opt-in：

```js
await ai.run({
  taskId,
  messages,
  returnMeta: true
});

// opt-in 返回
{
  text,
  profileId,
  provider,
  modelId,
  reasoningDepth,
  fallback: {
    used: false,
    primary: { profileId, modelId },
    errorCode: ''
  }
}
```

- 默认调用仍返回原字符串，保持兼容。
- 流式调用需要在最终完成值中提供同等元数据。
- UI 不展示原始错误栈，只保存可安全展示的错误类别或简短原因。

### 体重报告版本

每个周期仍保留一条报告记录，避免历史归档出现重复周期：

```js
{
  id,
  kind: 'weekly' | 'monthly',
  periodStart,
  periodEnd,
  metrics,
  versions: [
    {
      id,
      source: 'ai' | 'offline',
      generatedAt,
      payload: { summary, highlights, suggestions },
      model: { profileId, provider, modelId },
      reasoningDepth,
      fallback: { used, primary }
    }
  ],
  activeVersionId
}
```

迁移：

- 旧记录的 `ai` 内容迁移为第一个版本。
- `model === 'offline'` 迁移为 `source: 'offline'`。
- 无法确定实际模型时标记为“旧版 AI 结果”，不伪造模型 ID。
- 迁移采用读时归一化或幂等 schema migration，不能重复生成版本。
- 为旧代码兼容，可在过渡期从活动版本派生旧 `ai` 视图，但新写入以 `versions` 为准。

### 训练总结版本

同一周期记录按结果意图区分：

```js
{
  id,
  kind: 'summary_weekly' | 'summary_monthly',
  periodKey,
  results: {
    summary: { versions: [], activeVersionId: '' },
    deload: { versions: [], activeVersionId: '' }
  }
}
```

- 月总结只使用 `summary`。
- 周总结使用 `summary` 与 `deload`，各自最多 3 个版本。
- 旧 `content` 迁移到 `summary` 的第一个版本。
- 版本删除、切换和追加由纯 helper 管理，UI 不直接操作数组细节。

## 版本与回退行为

### 重新生成

- 使用当前任务已保存的模型与推理深度。
- 用户必须明确点击“重新生成”。
- 新请求成功后追加版本并切换到新版本。
- 请求失败时保留当前版本，不写入失败版本。
- 超过 3 个版本时删除最旧的未活动版本。

### 离线复盘

- 仅通过显式“生成离线复盘”触发。
- 作为普通版本保存并标记“离线规则”。
- AI 失败时不得自动调用离线生成。

### 备用模型

- `manual`：主模型失败，显示错误和“使用备用模型重试”。
- `automatic`：自动调用配置的备用模型，成功后显示提示并记录实际模型。
- 任何回退结果都必须显示实际模型，不能沿用主模型标签。
- 未配置备用模型时不显示无效重试入口。

## 风险与缓解

### 风险：范围跨 UI、路由和报告数据

缓解：严格按两个内部阶段实施；阶段一先稳定共享控件和路由字段，阶段二再迁移报告数据。

### 风险：旧调用依赖 AI 返回字符串

缓解：使用 opt-in `returnMeta`，默认返回类型不变；先补运行时测试再改报告调用。

### 风险：收藏迁移把同名模型映射到错误连接

缓解：只迁移唯一匹配；多连接同名时不猜测，用户可重新收藏。

### 风险：炫彩推理图标破坏暗色主题或可访问性

缓解：颜色只作为辅助；同时使用轮廓、填充、装饰差异，并检查暗色对比度与减少动态效果设置。

### 风险：吸附工具栏被虚拟键盘遮挡

缓解：使用现有 modal/sheet 容器滚动策略与可视视口测试，不使用固定到浏览器窗口的脆弱定位。

### 风险：报告迁移重复执行

缓解：迁移 helper 必须幂等；测试同一记录连续归一化两次结果不变。

### 风险：自动回退造成额外费用

缓解：默认 `manual`；只有用户逐功能明确开启后才允许自动回退，每次回退都提示。
